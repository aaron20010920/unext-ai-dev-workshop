# 可以直接複製的 prompt

今天全部要用到的 prompt 都在這裡。照順序用。

---

## Prompt 0 — 叫 Codex 把開發環境裝好（不用開終端機）

**用途**：node、git、gh、vercel 這四個命令列工具，交給 Codex 裝，你不用打任何指令。

**在哪用**：**ChatGPT 桌面版**的 Codex。（帳號要自己註冊、桌面版要自己裝
—— 這兩件 Codex 幫不了你，因為它住在裡面。）

**貼這段**：

```
請幫我把這台電腦的開發環境裝好。我不會用終端機，
每一步先告訴我你要做什麼，再執行。

1. 先檢查有什麼：node -v、git -v、gh --version、vercel -v
2. 缺的才裝（自己判斷我是 macOS 還是 Windows）：
   Node.js LTS、git、GitHub CLI (gh)、Vercel CLI
3. 帶我登入：gh auth login、vercel login
   需要我去瀏覽器點同意的時候，停下來告訴我
4. 最後把四個版本號印出來給我確認

清單以外的東西不要裝。需要管理員密碼的步驟先問我
```

**它會停下來問你密碼、要你去瀏覽器點同意 —— 那是正常的**，照著點就好。

**讀它的回報，不要無腦按同意。** 這是今天第一次練「驗收」：
它說要裝什麼、裝到哪裡，你看得懂再讓它做。

**過關條件**：最後看到四個版本號。少一個就跟它說少哪一個，它會補。

> 公司筆電擋全域安裝（`npm i -g` 失敗）的話，不用硬修 ——
> 走 [03-troubleshooting.md](03-troubleshooting.md) 的 Vercel Drop 那條路。

## ⭐ Prompt 1 — 召喚一位會問好問題的訪談員（今天最重要的一支）

**用途**：你只要許願，剩下的它問、你答，PRD 自己長出來。

**在哪用**：ChatGPT 或 Claude 的網頁版，開一個**新對話**貼進去。

**貼這段**：

```
你是一位資深產品經理，專長是把外行人模糊的願望，問成工程師做得出來的需求單。

我的願望是：
「＿＿＿＿＿＿＿＿＿＿＿＿」（← 換成你的，用最白話的話講，不用修飾）

我的處境（這幾條是硬限制，請放在心上）：
- 我不會寫程式，全程靠 AI 幫我改 code
- 我只有 3.5 小時
- 我的網站只有「一個輸入框 + 一次 AI 呼叫 + 顯示結果」這個結構
- 不能碰個資、金流、登入、資料庫

現在請你訪談我。規則：

1. 一次只問一題，等我回答再問下一題。不要一次丟一串問題給我
2. 最多問 6 題。問完就停
3. 只問「使用者」層面的問題（誰用、他要什麼、他看到什麼、什麼算成功）
   不要問技術問題（不要問我要用什麼框架、資料庫、部署在哪）
4. 不要用專業術語。我聽不懂 API、schema、endpoint 這些字
5. 如果我的回答太模糊，不要放過我，換個方式再問一次
6. 我如果說「我不知道」，你就給我 2-3 個具體選項讓我選

六題問完之後，產出一份 PRD，格式如下：

## 1. 一句話
我要做一個 ___，讓 ___ 可以 ___

## 2. 誰會用
- 使用者是誰
- 他打開的時候想幹什麼
- 他最怕看到什麼

## 3. 使用者做什麼、看到什麼
（一行一步，寫成「他做 X → 他看到 Y」。這段會直接交給 AI 工程師照做，
所以要具體到不會被誤解。禁止出現「介面友善」「智慧化」這種無法打勾的句子）

## 4. AI 在裡面做什麼
- 輸入：使用者給它什麼
- 輸出格式：條列 / 表格 / 分幾類（要具體）
- 規則：不確定的東西怎麼處理
- 人格：它是誰、什麼語氣

## 5. 今天做得完 vs 今天做不完
（依我上面講的硬限制，誠實切開。不要為了讓我開心就說什麼都做得完。
做不完的不要刪掉，列成一張清單放在下面）

## 6. 三條驗收條件
（每一條都必須是我能當場打勾或打叉的。
例：「貼 200 字筆記 → 吐出至少 3 條待辦，每條有負責人」）

## 7. 今天先不做到什麼
（一句話，誠實寫）

現在開始問第一題。
```

**它會怎麼跑**：它問一題 → 你答 → 它問下一題 → ⋯⋯ 六題後吐出 PRD。

**⚠️ 兩個要注意的**：

1. 它如果一次丟五題給你 → 回它「一次只問一題」
2. 它如果開始問技術問題（用什麼資料庫）→ 回它「這是技術問題，跳過」

## Prompt 2 — 我根本不知道要許什麼願

**用途**：腦袋空白的時候用這支暖身。

```
我是一個 ___（你的身分／實習的部門），
每天／每週都要做一些重複、無聊、花時間的事。

請你問我 3 個問題，幫我找出「最適合用 AI 做掉」的那一件。
一次問一題。

判斷標準（你評估用，不用告訴我）：
- 這件事要處理的是文字（不是圖、不是影片、不是要連別人的系統）
- 每次做的步驟差不多
- 做完的結果我看一眼就知道對不對

三題問完，給我 3 個具體的許願句，讓我挑一個。
```

---

## Prompt 3 — Review 完發現 PRD 不對，叫它改

```
第 ___ 節不對。

我要的是：___
你寫的是：___

只改這一節，其他不要動。改完把整份 PRD 重新給我一次。
```

> ⛔ 不要說「這份 PRD 不太對，重寫一份」— 它會整份換掉，你剛看過的好部分也會不見。

---

## Prompt 4 — PRD 沒有誠實切「做得完／做不完」

```
你把太多東西寫進「今天做得完」了。

重新評估一次：我不會寫程式、只有 3.5 小時、
網站結構只有「一個輸入框 + 一次 AI 呼叫 + 顯示結果」。

在這個限制下，重新切一次第 5 節。
今天做不完的，列成一張清單，不要刪掉。
```

## Prompt 5 — 把 PRD 交給 Codex 開工

**在哪用**：ChatGPT 的 Codex（連好你 fork 的 repo 之後）。

```
這是我的需求單：

（貼上你 review 過的 PRD 全文）

請照這份需求單改 starter-kit：

- 頁面：starter-kit/app/page.jsx
- AI 的人格與規則：starter-kit/app/api/ai/route.js 裡的 systemPrompt

規則：
1. 先跟我複述一次你理解的需求（第 3 節那幾步），等我說「開始」你才動手
2. 一次只改這兩個檔，不要新增其他檔案
3. 不要加登入、資料庫、檔案上傳
4. 不要動 package.json（不要裝新套件）
5. 改完告訴我「你改了什麼、我該去哪裡看效果」
```

> **第 1 條是保險**：讓它先複述，你就能在它動手前抓到誤解。
> 這一步省下來的時間，比它省的多。

## Prompt 6 — 只改一個小地方

**用途**：開工之後你會一直用這支。**一次只講一件事。**

```
只改 starter-kit/app/page.jsx：
把 ___ 改成 ___

其他都不要動。
```

範例：

```
只改 starter-kit/app/page.jsx：
把 APP_TITLE 改成「會議筆記整理器」，
PLACEHOLDER 改成「把你的會議筆記貼在這裡」。

其他都不要動。
```

---

## Prompt 7 — 改 AI 的人格與輸出格式

```
只改 starter-kit/app/api/ai/route.js 的 systemPrompt，改成：

你是一位嚴謹的會議秘書。
把使用者貼進來的筆記整理成三類：待辦事項 / 已做的決議 / 需要再確認的事。
用表格輸出，欄位是「類別 | 內容 | 負責人」。
沒寫負責人的填「未指定」，不要自己猜是誰。
不確定的內容放進「需要再確認」，不要編。

其他都不要動。
```

---

## Prompt 8 — 改壞了，回上一個能動的版本

⛔ **不要**跟 AI 說「修好它」— 越修越壞。

```
剛剛那次改動壞了。

請把 starter-kit/ 還原成上一個 commit 的狀態，
不要試著修，直接還原。

還原完告訴我，我會重新講一次需求。
```

或者在 GitHub 網頁上做：進你的 repo → **Commits** → 找到上一個綠色勾勾的
commit → 右邊 **⋯** → **Revert**。

---

## Prompt 9 — Vercel build 失敗，看不懂錯誤訊息

```
我的 Vercel 部署失敗了，錯誤訊息是：

（貼上 Vercel 那一大段紅字，全部貼，不要只貼最後一行）

我不會寫程式。請告訴我：
1. 這是什麼問題（用白話）
2. 我要改哪個檔的哪一行
3. 改成什麼

不要給我一長串可能原因，直接告訴我最可能的那一個。
```

---

## Prompt 10 — Demo 前，幫我準備要講的話

```
這是我今天做的東西：

（貼你的 PRD 第 1 節 + 網址）

幫我準備一段 2 分鐘的 demo 講稿，要講到三件事：
1. 我原本要花多久做這件事
2. 這個東西幫我做掉了哪一段
3. 今天沒做完的部分，接下來會怎麼長

不要吹牛，不要用「創新」「顛覆」這種字。
講得像一個實習生誠實報告自己做了什麼。
```

## 一張表：什麼時候用哪一支

| 你的狀況 | 用 |
|---|---|
| 想好要做什麼了 | Prompt 1 |
| 腦袋空白 | Prompt 2 → 再回 Prompt 1 |
| PRD 出來了但不對 | Prompt 3 |
| PRD 承諾太多做不完 | Prompt 4 |
| 要開始改 code | Prompt 5 |
| 改一個小地方 | Prompt 6 |
| 改 AI 的行為 | Prompt 7 |
| 改壞了 | Prompt 8 |
| 部署失敗 | Prompt 9 |
| 要上台了 | Prompt 10 |
